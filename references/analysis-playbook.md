# 分析算法手册 · Analysis Playbook

> 本文件定义「麦麦健康省钱顾问」如何把 3 路真实数据变成「今日餐盘」推荐。
> Skill 在 Step 3 分析对比阶段严格按此执行。所有输入均来自 MCP 真实返回。

---

## 一、营养筛选（健康维度）

1. **热量闸门**：组合总热量 ≤ 用户热量目标 × 1.1（留 10% 余量），超标的组合直接淘汰。
2. **蛋白密度排序**：`蛋白密度 = 蛋白质(g) ÷ 能量(kcal)`。密度 ≥ 0.10 视为「优秀高蛋白」，≥ 0.07 为「良好」。
3. **偏好过滤**：
   - 忌口关键词（如「油炸」「辣」）命中餐品名 → 剔除。
   - 「低钠」偏好 → 优先 sodium 低者。
   - 「不要含糖饮料」→ 剔除名称含「可乐」「雪碧」「糖水」等。

## 二、组合生成（从单品到套餐）

- 基础单元：每个 `list-nutrition-foods` 返回的餐品。
- 扩组合：生成 **单品 / 双拼 / 三件套** 三类组合（双拼=2 个不同餐品，三件套=3 个）。
- 每组合累加：总能量、总蛋白、总脂肪、总碳水。
- 剔除：总热量超目标、含忌口、或重复同一单品（除非买赠券明确需要）。

## 三、优惠匹配（便宜维度）

对通过营养筛选的组合，套 `available-coupons`：

1. **门槛校验**：券 `threshold` 为「满X」时，组合需有可对应原价 ≥ X；「无门槛」直接适用。
   - 若组合无单价（仅营养数据），按「优惠提示」处理：列出「本组合可叠加 X 券（减Y/折扣）」，不强行算到手价。
2. **优惠额计算**：
   - `减X` → 直减 X 元。
   - `X折` → 到手 = 原价 × X/10。
   - `买N赠M` → 省 = 第 (N+1) 份单品均价（需组合内数量 ≥ N+1）。
3. **活动叠加**：若 `campaign-calendar` 有「进行中」且类型为「优惠/会员日」的活动，提示「可与该券叠加，更划算」，但不虚构叠加规则。
4. 每个组合记录：`适用券名`、`省多少`、`到手价`（有单价时）。

## 四、综合评分（排序出 Top）

对候选组合归一化打分（0–100）：

- **营养分 N** = min(蛋白密度 / 0.12, 1) × 100（密度越高越满）。
- **热量适配分 C** = max(0, 1 − |组合热量 − 目标| / 目标) × 100（越贴近目标越满）。
- **省钱分 M** = min(省多少 / 15, 1) × 100（省 15 元及以上即满分；无单价时用「有可用券」记 60 基线）。

`综合 = N×0.5 + C×0.3 + M×0.2`，取 Top 1–3 输出。

## 五、解释文案模板

每套方案末尾给一句理由，从下面挑最贴切的：
- 「高蛋白低卡，正好卡在你的热量目标内。」
- 「叠加 [券名] 后到手 ¥X，今天这顿性价比拉满。」
- 「[活动名] 进行中，顺手薅一波更香。」
- 「脂肪/钠偏低，健身或控糖人群友好。」

> 原则：解释必须能被数据支撑，不空泛吹捧。
